Scope: the six confirmed ACQ findings in the local Cybertest report, plus its raw-error and stale active-organization candidates. Acquire branch `codex/security-report-remediation` starts from local main `90e5cf0`. The independent legacy branch `codex/security-token-integrity` starts from its local main `08aa426`. No database migration, account connection, provider write, send, merge or deployment is part of this change.

Production's anonymous401 was verified in the prior review. This change does not restore direct Gmail or certify every replacement setup flow. |

| ACQ-003 — browser mutation CSRF | Next Proxy covers all API routes and checks configured APP_URL Origin on browser mutations. Requests with bodies require application/json (DELETE is Origin-protected without a JSON requirement); existing bodyless actions remain compatible. Better Auth and explicitly bearer/webhook-owned route prefixes retain their own authentication. A Bearer header cannot exempt a browser API. Tests cover sibling/foreign/null/missing origins, JSON media type, proxy-host spoofing, matcher coverage and bodyless actions. Actual production-build requests return403 for foreign-Origin text/plain and415 for trusted-Origin text/plain before session/database access. |
| ACQ-004 — short GCM tags | Acquire has removed both old decoders under channel retirement. Its new vault validates full decoded tags. Independent legacy Gmail/WhatsApp decoders now require canonical four-segment v1 envelopes,12-byte IVs and16-byte tags, with authTagLength16. Old valid full-tag v1 data remains readable; shortened4/8/12/13/14/15-byte tags and malformed envelopes are rejected. No stored credentials or schema were changed. |
| ACQ-005 — redirect escape | Reject backslashes and ASCII controls; parse against a fixed trusted origin, compare origins and return normalized path/query/fragment. Tests reproduce the original escape and cover controls, protocol-relative paths and valid normalization. Browser verification uses synthetic intercepted authentication responses, without real login or database writes. |
| ACQ-006 — framing/headers | Every Next response receives X-Frame-OptionsDENY, nosniff and a CSP with frame-ancestors none/object-src none/base-uri self/form-action self. The policy deliberately scopes embedding/document defenses and preserves Next inline bootstrap and React styles; it is not a claim of comprehensive script-injection protection. Production-build HTTP verification and a different-origin Chrome iframe confirm framing is blocked. No hosting change is applied here. |

## Additional report candidates

Application session lookup now checks current membership for both user and active organization on every call, returning null after revocation or membership-query failure. Other Better Auth sessions can retain stale organization IDs after member removal; the application must not treat that cached ID as authorization. Tests cover removed/current membership, repeated lookup, no active organization, signed-out access, repository failure and exact query scope. This is local synthetic verification, not a new production membership-removal experiment.

Campaign tick returns a generic500; outreach drafting returns a generic502 and omits raw provider exception text from logs. Regression tests inject synthetic private exception contents and prove they are absent from responses/logs.

Personal-domain email remains a product-policy question, not an authorization defect demonstrated by the original report. The report's current secret candidates were fixtures/placeholders; historical validity/rotation is not established. Scanner parsing gaps, complete authenticated role/tenant/provider tests and other original coverage gaps are not converted into security guarantees by these fixes.
