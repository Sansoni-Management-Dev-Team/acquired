# Gmail campaign automation

## WhatsApp campaign delivery

WhatsApp steps now compile to the same authenticated `/api/internal/campaigns/step` callback as email and LinkedIn. Acquire renders each message and sends through the sequence owner's existing WhatsApp service connection. Publishing requires `WHATSAPP_SERVICE_URL` and `WHATSAPP_SERVICE_SECRET`; enrolment requires a connected WhatsApp account and a contact phone number with an explicit international country code. Personalized messages are limited to 4000 characters.

WhatsApp uses the existing campaign send claims, contact holds, sending windows and shared mailbox caps/spacing. Provider submission IDs are recorded before advancing; callback replays do not resend recorded messages. Unresolved attempts and ambiguous provider responses are held for review rather than automatically retried. n8n owns waits and retries for scheduling holds. Gmail remains required for campaign enrolment and email reply monitoring. WhatsApp and LinkedIn replies are not yet monitored; WhatsApp submission confirms provider acceptance, not delivery or reading. No database migration is needed.

## n8n sequence runtime (migration 0013)

Publishing with `CAMPAIGN_N8N_ENABLED=true` creates and publishes one n8n workflow per immutable sequence version. The workflow contains a Webhook trigger, named email steps, a Wait node for each sequence delay, and Wait nodes for temporary send holds. A contact enrolment starts one execution of its pinned version. n8n owns the execution and timing; Acquire receives each step callback, checks Gmail replies and suppression, applies mailbox caps and business hours, then sends through the contact owner's Gmail grant. Workflow payloads contain the enrolment and version IDs, not Gmail tokens or email bodies.

Migration `drizzle/0013_campaign_n8n_runtime.sql` was applied locally and in production with specific approval. It adds the workflow ID to versions and a runtime/dispatch marker to enrolments. Existing enrolments default to `legacy`; the existing minute scheduler continues sending those and scanning replies. New n8n enrolments are dispatched by that scheduler, while their send steps are driven by n8n. A failed dispatch remains unstarted and is retried on the next tick. The sync endpoint provisions workflows for versions published before cutover without moving their current contacts.

Cutover completed on 25 September 2026: migration 0013 was applied with specific approval; the code, `CAMPAIGN_N8N_URL`, `CAMPAIGN_N8N_API_KEY`, `CAMPAIGN_N8N_WORKER_CREDENTIAL_ID`, and `CAMPAIGN_APP_URL` were deployed; authenticated `POST /api/internal/campaigns/sync` created the workflow for the previously published version; and `CAMPAIGN_N8N_ENABLED=true` was deployed. The production Header Auth credential sends the existing `OUTREACH_WORKER_SECRET` to the Acquire domain. The scheduler workflow remains published for legacy contacts, n8n dispatch and reply scans. The production n8n plan cannot restrict API-key scopes, so the user explicitly authorized a non-expiring full-scope key for ongoing sequence publishing. Rotate it in n8n and Vercel together if it is ever replaced.

The production `First Sequence` v1 workflow is active at `https://n8n.mlai.au/workflow/0IQl0zTZ8GFXykNk`. A webhook execution with a nonexistent enrolment reached Acquire through the Header Auth credential and returned the expected 404; this checked authentication without sending Gmail. The campaign studio shows the n8n workflow link. The mandate's production mailbox is disconnected, so a live Gmail send from that account has not been tested.

## Safety rules

- Sends occur only on weekdays from 09:00 to 17:00 Australia/Melbourne, at least 60 seconds apart per mailbox, and under the mailbox's rolling 24-hour cap.
- Before each send, Acquire checks the contact record, organisation-wide email holds, legacy suppressions, the sender's own Gmail grant, and the sender's Gmail inbox for new inbound mail. The first email also checks for any prior Gmail conversation; follow-ups hold if an unrecorded manual outbound email appeared after subscription.
- An inbound message creates a deduplicated event and an organisation-wide hold for that email address, stopping every active enrolment for it. Manual pause is resumable. A reply stop is not automatically resumable.
- The `(enrolment, step)` send record is unique. If a Gmail request's result is ambiguous, it is marked `unknown` and no automatic retry occurs. This avoids double-send; reconciliation and manual review are required before continuing.
- A contact becomes exclusively assigned to the subscribing user for campaign outreach. The database rejects an enrolment whose owner does not match that assignment or the Gmail connection owner.
- LinkedIn and WhatsApp are not enabled by this migration or worker. Their future adapters must use the same send guard and contact hold path, with connected accounts tied to the subscribing user.
