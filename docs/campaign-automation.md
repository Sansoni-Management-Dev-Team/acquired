# Gmail campaign automation

This build adds a separate Gmail-first campaign studio at `/mandates/:id/outreach/campaigns`. The existing draft-only outreach path remains unchanged. A sequence draft is editable; publishing creates an immutable version. Each enrolment stores its version, owner, contact, recipient email, and the owner's Gmail connection. A confirmation dialog shows the first **published** action before enrolment.

## Local no-send validation

The five campaign migrations have been applied to the dedicated OrbStack database at `127.0.0.1:5434/project_acquire` and to the production Supabase database with the user's approval. Production's ledger and migration hashes were verified through `0007` before applying `0008`–`0012`; the ledger and hashes were checked after each migration. No data was copied between environments.

The local Compose stack includes an in-memory delivery sink and a separate n8n instance. The sink accepts synthetic email sends, inbound replies, manual outbound events, and simulated ambiguous provider responses. It has no external messaging credentials. `CAMPAIGN_TEST_SINK_URL` is rejected unless Acquire is running in local development against the dedicated loopback OrbStack database and sink. `CAMPAIGN_TEST_SEND_ANYTIME` is likewise confined to that setup.

With the local Postgres, sink, and n8n services running, start Acquire with `CAMPAIGN_TEST_SINK_URL=http://127.0.0.1:18094/ CAMPAIGN_TEST_SEND_ANYTIME=true OUTREACH_WORKER_SECRET=local-campaign-test-only pnpm dev`. Import `ops/n8n/acquire-campaign-local.json` into the local n8n instance, then run `CAMPAIGN_E2E_LOCAL=1 OUTREACH_WORKER_SECRET=local-campaign-test-only node scripts/test-campaign-local.mjs`. The test creates synthetic users, contacts, and a campaign; exercises the authenticated API and the n8n-triggered worker; verifies the sink deliveries; and deletes its database fixtures. Set `CAMPAIGN_E2E_BROWSER=1` to keep the synthetic fixtures available for a browser check until Enter is pressed. The local workflow is currently unpublished, so its minute schedule does not run continuously. The test invokes it through the n8n CLI.

For failure and rate-limit checks during a Melbourne weekday sending window, start Acquire with the sink URL but without `CAMPAIGN_TEST_SEND_ANYTIME`, then set `CAMPAIGN_E2E_EXTENDED=1` on the test command. This exercises mailbox-check outages, stale reply scans, unknown-send reconciliation, one-minute mailbox spacing, and the rolling daily cap. Add `CAMPAIGN_E2E_RESTART=1` to pause after an accepted send with a lost response; restart Acquire with the same sink settings, then press Enter to verify reconciliation after process restart. The fixed-date domain test also checks both business-hour boundaries, a weekend, and the daylight-saving transition.

The local n8n owner login is stored in the ignored, permission-restricted `.local-data/n8n-local-login.json`. To check the actual minute schedule, keep Acquire in sink mode, publish the local workflow and restart n8n, then watch for a synthetic sink delivery and an n8n `trigger` execution. Unpublish the workflow and restart n8n immediately after the check. The imported workflow needed to be saved once in the n8n editor before its first publish because the CLI import did not create a version-history row. The local schedule was verified and then unpublished; it is not active now.

## Activation checklist

1. `drizzle/0008_campaign_automation.sql` through `drizzle/0012_campaign_rls_roles.sql` were applied to production with explicit approval for those five migrations. The production ledger now has 13 matching entries. **Do not apply any future migration without explicit approval for that specific migration.**
2. The existing database login has `BYPASSRLS` locally. Migration 0012 creates non-bypass campaign user and worker roles and grants the login membership. Every campaign transaction uses `SET LOCAL ROLE` before accessing campaign tables; the code rejects a role that still bypasses RLS. Campaign tables use forced RLS with transaction-local organisation/user context. The campaign user role also receives owner/organisation-scoped RLS on the legacy tables it reads, including Gmail connections, contacts, mandates, targets, suppressions, membership and audit events.
3. `OUTREACH_WORKER_SECRET` is set in Vercel Production. The deployed worker endpoint returned HTTP 200 with zero processed enrolments when called with the secret and HTTP 401 without it. Reconnect each intended sender's Gmail to grant both `gmail.compose` and `gmail.readonly`; old compose-only grants are not eligible for automation.
4. `ops/n8n/acquire-campaign-tick.json` has been saved as an unpublished workflow on `n8n.mlai.au`. Its request targets `https://project-acquire.vercel.app/api/internal/campaigns/tick`. Create an n8n **Header Auth** credential with name `Authorization` and value `Bearer <OUTREACH_WORKER_SECRET>`, then select it in the HTTP Request node. Do not place the secret in workflow JSON or use `$env`: n8n 2.x blocks node access to environment variables by default. Test the request, then activate the workflow. n8n only triggers the worker; it has no Gmail credentials or sequence state.
5. Test with a controlled mailbox and contact, including existing conversation, reply, manual pause/resume, retry after a simulated timeout, and two simultaneous worker calls. No production contacts should be subscribed before these tests pass.

## Safety rules

- Sends occur only on weekdays from 09:00 to 17:00 Australia/Melbourne, at least 60 seconds apart per mailbox, and under the mailbox's rolling 24-hour cap.
- Before each send, Acquire checks the contact record, organisation-wide email holds, legacy suppressions, the sender's own Gmail grant, and the sender's Gmail inbox for new inbound mail. The first email also checks for any prior Gmail conversation; follow-ups hold if an unrecorded manual outbound email appeared after subscription.
- An inbound message creates a deduplicated event and an organisation-wide hold for that email address, stopping every active enrolment for it. Manual pause is resumable. A reply stop is not automatically resumable.
- The `(enrolment, step)` send record is unique. If a Gmail request's result is ambiguous, it is marked `unknown` and no automatic retry occurs. This avoids double-send; reconciliation and manual review are required before continuing.
- A contact becomes exclusively assigned to the subscribing user for campaign outreach. The database rejects an enrolment whose owner does not match that assignment or the Gmail connection owner.
- LinkedIn and WhatsApp are not enabled by this migration or worker. Their future adapters must use the same send guard and contact hold path, with connected accounts tied to the subscribing user.
