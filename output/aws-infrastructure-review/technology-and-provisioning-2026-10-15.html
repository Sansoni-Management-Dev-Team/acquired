Migration boundaries and realistic first-week milestone

First-week target: access and ownership, Terraform UAT baseline, container builds/deployment, separate database restore/schema rehearsal and bounded research migration proof. Production is a separate cutover with recorded account/campaign ownership, in-flight waits, original receipts, unresolved-send handling, encryption keys and state preservation.

Cloudflare is more than a runtime change. Durable checkpoints, shared pacing/cooldowns, serialized Firmable credential renewal, caches, browser/search quality and PDF extraction all need replacements. Step Functions Standard supports longer runs; Express stops at five minutes. Direct HTTP tasks have a 60-second timeout and execution payloads have a 256-KiB limit, so current long callbacks and page payloads require task workers/asynchronous completion and object references. Workflow types; Quotas.

Company ECS and HTTPS ingress can host the containerized application/services. Bedrock requires approved model/region access and provider prerequisites; inference selection is not equivalent to placing an Anthropic API key into the existing OpenRouter adapter. ECS load balancing; Bedrock access.

Keep n8n initially to preserve campaign timing; rewriting it simultaneously increases scope. Existing legacy DigitalOcean resources still cost US$52/month but code removal does not authorize stopping them or discarding historical state. Their decommissioning needs its own reviewed recovery/retention decision. Full Unipile production parity and sending activation must be assessed separately from healthy containers.

Database safety: no migration, restore, initialization, role/schema change or auto-migration has been performed by this review. The existing specific migration approvals are historical and cannot be reused for new AWS targets. Production-to-UAT data copying and new live sends are not part of the provisioning request.
