# PostgreSQL communications storage

The repositories import no database driver, Acquire module or framework. Supply a `SqlPool` wrapper; the driver must destroy a checked-out connection when `release(error)` receives an error. There is no migration/startup path, provider fallback or production memory store.

`createPostgresWebhookRepository` captures encrypted raw receipts and claims them with database-clock leases. With `EventCodec` configured, `finish` commits typed encrypted events, required subscriber outboxes and the inbox terminal state in one transaction. It checks current immutable account/configuration/generation/grant evidence, receipt bytes, exact lease tokens and semantic fingerprints; conflicting event content becomes a review event and invalidates service coverage. Retained codec keys support old ciphertext and duplicate evidence. It does not apply application person policy.

`createPostgresOutboxRepository` claims scoped subscriber work and acknowledges only an exact application commit receipt, fingerprint and original claim token. Accepted historical generations remain deliverable; current grants are still required. Lost commit responses replay without reopening terminal work. If reply-consumption schema 003 is installed, an explicit tenant-first `replyBarrier.lock` is required before other locks; an absent implementation fails closed.

`createPostgresAuthStateRepository` stores only nonce digests, immutable server scope and expiring single-use setup authorization. A required authenticated notification port checks nonce correlation; a required trusted binder verifies actual provider ownership and persists its exact connection/generation inside the same transaction. Deterministic result addresses preserve original results after a lost response or later reconnect. These ports have no default implementation: callback account IDs alone do not establish ownership. The SQL callback wrapper prevents direct transaction lifecycle escape, but is not a SQL security sandbox.

The independent package exports `EventCodec` and the bounded `createOutboxDeliveryWorker` alongside these repositories. They validate evidence and sequencing, not fresh complete provider coverage. Real credentials/keyring configuration, immutable ingress routing, review latches, tenant fences, identity authority, account lifecycle/history reconciliation and send admission must be composed before activation. Acquire separately owns its receipt/holds/stops/audit transaction before service ACK.

Scripted-driver tests check guards and failure protocol. Opt-in actual PostgreSQL tests live in Acquire's `src/db/communications-*-local.integration.test.ts` so `pg` remains an injected runtime dependency. These check the exact isolated OrbStack database system identity and require individually approved schemas; they never create tables or grant permissions. Synthetic immutable service history remains with retired accounts/grants; rollback-only identity characterizations leave no rows. See `docs/communications/durable-replies-tdd.md` for evidence and current limits.
